# GuideOS 0.4.2.01

GPU composition, browser terminal handoff, media startup/resource repairs and
release naming integration. Signed sequence 60, compatible base sequence 59
(`0.4.2`). Source `VERSION`, signed manifest and visible About agree.

## Changes and failure evidence

- The Home wheel, highlights, cards, pointer and overlays use cached textures
  with GPU rotation, translation and blending. Guide View retains layout,
  text and control semantics. The Mali-G31/Panfrost adapter discovers the
  connected sun4i-drm internal panel rather than assuming a DRM card number.
  Restoration to the existing framebuffer precedes Browser/Video handoff.
  Native presentation failure has a bounded software recovery path; failed
  restoration cannot silently grant the display to another owner.
- Returned boot `d386c9d60223439485a097265cea78b9` shows Browser failing in its
  terminal-switch preparation with status 124, before Weston starts. The shell
  had selected graphics mode while leaving its virtual terminal in automatic
  mode, which blocks terminal switching. It now explicitly controls terminal
  release and acknowledges switches only while its display lease is suspended.
  Resume reopens the terminal descriptor; shutdown also restores the original
  terminal mode. Browser keeps its separate unprivileged account and seat.
- Video now waits for an initialized output and dimensions within the existing
  eight-second startup budget. Creating the IPC socket alone no longer marks
  the decoder ready. Shader caching, a half-second audio output buffer, bounded
  audio scheduling priority, and a larger media memory allowance reduce cold
  startup and scheduling pressure. Codec decoding remains software; no hardware
  decoder or measured frame-rate improvement is claimed.
- The returned media service reached 194.2 MiB with a 192 MiB pressure threshold.
  The threshold is now 320 MiB with a 384 MiB hard limit. Missing RTKit had also
  prevented real-time audio scheduling; PipeWire and its media client now use
  matching priority 20 within explicit scheduling/time limits. These observations
  do not establish the exact cause of the user's stuttering or first-open error.
  Player errors and decoder readiness now reach the journal for the next capture.
- [Release naming](RELEASE_NAMING.md) preserves legacy labels while requiring
  new 0.4.2 builds to use the selected two-digit revision suffix. Upgrade and
  downgrade decisions continue to use signed numeric sequences. About receives
  actual system status. NDI 1.0.2 discovers current and legacy update folders by
  sequence, removing the r21 default. Existing signed archives retain their names.
