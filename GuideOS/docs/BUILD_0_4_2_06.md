# GuideOS 0.4.2.06 — service repairs and approved eclipse animation

The owner reported Storage unavailable, every Node A action returning Home, and
Browser controls failing with UInputError on the deployed 0.4.2.05 Deck.
Authenticated live diagnostics confirm Storage repeatedly failing to load exfat.
The deployed kernel build disables EXFAT_FS, NLS_UTF8 and INPUT_UINPUT. These
providers were installed separately for the previous kernel; the Cedrus packaging
omitted them. Live diagnostics confirm the new kernel boot and Panfrost GPU shell
rendering, but do not establish actual Cedrus decoding.

Responsibility stays with the board's driver package, systemd service startup and
the shell's existing input owner. The repair builds three additive modules from
an isolated copy of the exact installed kernel source/configuration and exported
symbols. Existing Image, DTBs, decoder/joypad modules and private media runtime
remain unchanged. Future clean Cedrus builds explicitly enable all three modules.
No storage permissions, mount requirements or Browser input checks are bypassed.

Node controls now resolve A through the panel's semantic focus identity, including
session, discovery and pairing rows. Disabled or stale focus cannot fall back to
Back. Existing B navigation remains intact, and a pending Node request cannot be
replaced by another A action. Trust refresh retains its single existing worker
and pending request instead of creating new executors.

Source checks pass 130 focused tests, including actual rendered Node regions,
D-pad-to-A dispatch, disabled rows and worker/request retention. Two previously
identified legacy Wi-Fi fixtures are excluded; this is not a whole-repository pass.
Module verification checks the expected configuration delta, unchanged kernel
Image/Module.symvers, matching release/vermagic and every imported kernel export.
This kernel does not enable symbol-version CRCs; physical module loading remains
an acceptance requirement, not an inference from matching exports.

The root-only candidate includes all three modules, installed dependency indexes,
uinput boot loading and the signed UI repair. Its image-only UI payload rejects
activation against the currently deployed sequence: a standalone UI update cannot
deliver the missing system drivers. Unchanged, verified read-only signed release
files share filesystem blocks with the previous immutable release; changed code
and owner state do not. Earlier releases are retained, and the 64 MiB free-space
reserve remains mandatory. Preparation uses the previous verified 0.4.2.05
root image as a historical base. Before any Seed write, capture the returned card
again and rebase this bounded repair onto its current root so changes made during
this Deck session remain intact. Do not reuse the historical candidate as a fresh
owner-state capture. No boot partition write is required for this repair.

The initial repair-only historical-base candidate passes a read-only sealed-image check: installed
signature and all 77 payload hashes match; repaired Node sources match the working
source; 5,311 existing directories retain their types, ownership and modes; the
installed ARM64 kmod resolves each new driver for 7.2.7-guide-cedrus0. Existing
file/link comparison and filesystem checking also pass. Available root space is
92,573,696 bytes. The image receipt explicitly records that the card has not been
written and physical acceptance has not occurred. Three rejected assembly attempts
remain recorded beside the accepted candidate, covering a host-release selection
error, index permissions and an insufficient free-space reserve; none is eligible
for deployment.

“Planegotchi 0.1 (2)” for this update. The final corona revision 2 is pinned under

`3c0d08b24428d49180da51460e9c9cd076d86693057898e2808ab1573abc5d6d`.

10 fps and 7.5 seconds. The irregular connected corona and 12-pixel G/O/S
clearances follow [the approved design](../design/boot-eclipse-animation-0/FINAL_CORONA_2.md).

The consolidated `animation-candidate` replaces only the installed stream at
`/usr/share/guideos/boot-animation/boot-eclipse-v1.rgb565a`, alongside the existing
three service-driver and Node repairs. Player, runner, console helper, boot unit
and shell handoff drop-in are hash-checked against the previous image and retained.
The FAT boot partition and kernel Image are not changed. The original repair-only
candidate and old animation remain preserved on the development PC.
The consolidated image also passes sealed signature/source, directory metadata,
installed driver resolution, boot-contract and filesystem checks. Its installed
animation hash equals the pinned approved asset; available root space remains
92,573,696 bytes. No Seed write or physical playback is claimed.

The stale source validator required a Before line in the boot unit even though
the effective ordering already exists as After in the shell drop-in. Validation
now checks that actual drop-in and the notify/handoff contract, including the
installed files when given a staged root. The installer uses a shared drop-in
file whose bytes equal the existing installed configuration. No runtime ordering
is altered. Eight Linux tests pass, including a child readiness/acknowledgment
exchange that verifies Home startup notification before child completion and
display-release publication after exit. This is lifecycle evidence with a test
child; actual DRM/KMS playback and handoff still require Deck acceptance.

Physical acceptance after installation: Storage starts and lists the external
card; Node A invokes each highlighted enabled action and B returns correctly;
Browser opens with controller navigation and returns cleanly to its launching
screen; the complete new eclipse plays and transfers display ownership cleanly
to Home. Preserve the existing exclusion of Start, Power and Reset from exercises.
Actual NDI streaming, Cedrus decoding and card reinsertion remain separate checks.
