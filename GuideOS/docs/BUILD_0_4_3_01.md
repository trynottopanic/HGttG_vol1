# GuideOS 0.4.3.01

First 0.4.3 revision, release sequence 65. Rebased from the inserted Seed's
freshly captured 0.4.2.05 root (sequence 64), including its owner state and
configuration. The prepared 0.4.2.06 repairs are incorporated here; that revision
was never written. This is a root-image update, not a standalone network payload.

**Seed write complete:** the guarded writer exited successfully and the full
2 GiB root readback equals the sealed image. The boot region, data partition and
reserved tail match their prewrite hashes. Physical boot and feature acceptance
remain pending.

## Included changes

- Integrates the approved Planegotchi 0.1 handoff as a read-only world viewer:
  128×64 shared tiles, three continents, 24 islands, a nearest-sampled rotating
  globe and full-resolution regional maps. Home has an ordinary selectable world
  window; the existing Home art, wheel, shortcuts and real status bar are retained.
- Uses the approved quiet galaxy, globe/panel geometry, typography, white arrow
  and small blue land-selection dot. Statistic totals are explicitly mock data.
- Left stick moves the pointer; A and stick click activate the same visible land
  identity; L/R turn the globe; Select pauses/resumes; regional D-pad pans; B
  returns through the viewer to its launch context; Menu opens Home. Global
  volume, power and display ownership remain with the shell.
- Adds bounded validation, visible asset failures, one-region raster retention,
  fixed GPU texture keys, cached panels and optional native CPU projection.
  Hidden or display-leased views stop advancing. GPU composition remains with
  the existing renderer. No world simulation is introduced.
- Incorporates Node semantic focus/pending-action fixes, matching exFAT/UTF-8
  and uinput kernel modules, and uinput boot loading. The existing
  7.2.7-guide-cedrus0 kernel, DTBs and joypad driver are preserved.
- Installs the approved final-2 75-frame, 7.5-second boot animation under the
  existing boot player/service ordering.
- Repairs media inventory timestamp handling and bounded audio-status reads,
  rejecting unavailable/stale/invalid state before acquiring output ownership.

## Review and verification

See the [review report](../build/release-0.4.3.01/REVIEW.md) for resolved findings
and evidence limits. The requested Code Review connector exposed only PR CI
checks, so the high-detail local review was performed directly. No connector or
independent human review is claimed.

Focused current-source checks passed 88 tests. Deployment, media, storage and
browser/boot checks passed 82, 61, 36 and 15 tests respectively. The installed
ARM64 audio/GStreamer suite passed 31 tests. The host audio environment lacked
Gst, and the broad historical shell suite still has reproduced obsolete fixture
failures; neither result is represented as a complete repository-suite pass.

Installed ARM64 Python/C projection matched nine independent frame references;
all 27 regional maps and the actual shell/input routes passed. 1,411,344 displayed
globe samples were checked for exact nearest-sample land identity. Approved
idle/quarter/opposite globe crops match the visual references. A real
unprivileged host Weston/WebKit session passed browser controls, keyboard and
cleanup checks. Host execution and emulation are not Deck performance evidence.

The image's signature covers 109 payload files. Independent preservation checks
cover 34,969 existing entries, including 4,041 owner/configuration entries.
The previous immutable release is retained. Only reviewed deployment records,
module indexes, the boot asset and media timestamp repair change existing files.
Available root space is 91,795,456 bytes.

The guarded root-only writer verifies the exact reader model, serial, byte size,
USB/safety flags, partition geometry and absence of drive/folder mounts. It checks
all reviewed file hashes, the captured files and live boot/root/data/tail hashes,
then writes exactly 2 GiB starting at byte 135,266,304. It flushes and compares the
full root readback and rechecks boot/data/tail. The
[installation receipt](../build/release-0.4.3.01/release-candidate/installation.json)
is the authority for actual card-write completion; a source/image pass is not.
The [prewrite audit](../build/release-0.4.3.01/release-candidate/seed-prewrite-audit.json)
and [writer transcript](../build/release-0.4.3.01/release-candidate/seed-install.txt)
record the live capture match, bounded write and successful readback. The seal
uses immutable prewrite metadata; the current candidate records the completed
write separately. Image-check records remain evidence of the prewrite image.
